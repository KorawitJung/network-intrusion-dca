Can a model catch a cyberattack it has never seen before?

Four plain questions about detecting attacks in network traffic, answered with five days of labelled traffic from a research testbed (CIC-IDS2017).

Q1

How much of the traffic is an attack, and which attack type is most common?

About one flow in 6 is an attack, mostly flooding and scanning.

How to read this chart
Left: each bar is a kind of traffic, blue for normal and red for attacks. The scale is logarithmic so that rare attacks stay visible; read the labels for exact counts. Right: how many attack flows were recorded on each day, coloured by type.
What the data says
83.1% of flows are normal and 16.9% are attacks. DoS (7.7%), DDoS (5.1%), PortScan (3.6%) make up almost all of them. Brute force, Web attack, Botnet, Infiltration, Other are each under 0.4%. Monday had no attacks. Each day has its own attack types.
What it means
The loud attacks dominate the count: flooding a server (DoS, DDoS) and probing for open doors (port scan) generate huge numbers of connections. The quiet ones, such as botnet traffic or infiltration, are a tiny share of traffic, which is exactly what makes them hard to notice. The attack share here was set by the lab's schedule and is far higher than on a real network.

Q2

What does attack traffic look like next to normal traffic?

Different attacks look nothing alike, and some look just like normal traffic.

How to read this chart
Each row is a kind of traffic and each panel is one measurement. The box covers the middle half of flows, the line inside it is the typical (median) value, and the whiskers cover 90% of flows. Compare each attack row with the Benign row at the top. Scales are logarithmic.
What the data says
A typical normal connection lasts 46.80 milliseconds. A typical port-scan flow lasts 0.05 milliseconds, while DoS flows last 63 seconds. Botnet boxes largely overlap the Benign boxes.
What it means
There is no single signature of 'an attack'. A scan is a burst of tiny, instant connections; a DoS holds connections open for a long time; botnet traffic is built to blend in. A detector tuned to one of these patterns will not automatically recognise the others, which sets up Q4.

Q3

Can a model tell attacks from normal traffic?

Yes: it catches 99.7% of attacks when it has seen examples of every type.

How to read this chart
Each bar is one way of testing the same model. The blue bar tests it on a random 30% of flows from all five days, so every attack type it meets in the test also appeared in its training data.
What the data says
The model catches 99.7% of attacks, and 99.4% of its alerts are real attacks. Its weakest common type is Botnet at 80%.
What it means
This is the kind of score usually reported for intrusion-detection models, and it looks close to perfect. Q4 shows why it should not be taken at face value.

Q4

Can it catch attack types it has never seen before?

Mostly no: it catches 28.9%.

How to read this chart
Each attack type has two bars. Blue: the share caught in the random-split test from Q3. Red: the share caught when the model is trained on Monday to Thursday and tested on Friday, whose attack types never occur earlier in the week. 'Not in this test' means that attack type did not occur on Friday.
What the data says
On Friday the model catches 50% of DDoS, 0.1% of PortScan, 0% of Botnet. Overall that is 28.9% of attacks, down from 99.7%. When it does raise an alert it is still right 99.6% of the time; it simply stays silent on what it has not seen.
What it means
The model learned to recognise the specific attacks it was shown, not attacks in general. A near-perfect test score says little about tomorrow's attack. Defences built on this kind of model need retraining on new attack types and a second layer that flags unusual behaviour.

GLOSSARY

The terms used on this page

Flow
One conversation between two computers, summarised as a single row: how long it lasted, how many packets, how much data.
DoS / DDoS
Flooding a server with requests so real users cannot reach it. DoS comes from one machine, DDoS from many at once.
Port scan
Knocking on every network 'door' of a machine to find which ones are open.
Brute force
Guessing passwords by trying many of them, here against FTP and SSH logins.
Web attack
Attacking a website's login or input forms (password guessing, cross-site scripting, SQL injection).
Botnet
An infected computer quietly taking orders from an attacker.
Infiltration
An attacker already inside the network, moving from one machine to others.

Before you quote these numbers

  • The traffic was generated in a lab testbed in 2017. Attacks were run on a schedule, so the share of attacks is far higher than on a real network.
  • Friday's attack types do not occur on earlier days, so Q4 measures detection of unseen attack types, not the same attacks later in time.
  • Published critiques report labelling errors in the original files; this project uses them as distributed.
